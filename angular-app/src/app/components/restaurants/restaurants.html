Filtering this list happens entirely in your browser, so no request reaches the API. The browser agent still knows: each filter sends addPageAction('restaurant_filter_applied') with the filter and how many restaurants were left. Opening a menu, adding to the cart, starting checkout and placing the order each send one too. This page loads its restaurants from GET /api/restaurant. New Relic times every call, so you can see how fast the list comes back. Opening a restaurant calls GET /api/restaurant/by-name/:name. New Relic groups them under one transaction name and keeps the real URL, so you can see which restaurants get the most visits. Not every request has to succeed. This groups the same requests by HTTP status code. If a menu ever fails to load, it shows up here before anyone tells you.
